基于上一轮的批判与优化思路，我为你重构了一份**务实落地版完整技术方案**。

这份新方案的核心原则是：**砍掉华而不实的过度设计，用“微服务化”替代“全家桶绑架”，用“分期交付”替代“大跃进开发”**。我们将目标锁定为**4人团队、6周内交付一个可稳定演示、数据真实可靠的MVP（最小可行产品）**，并保留清晰的二期迭代路径。

# 项目技术方案（V2.0 务实迭代版）

## 一、 整体架构调整：从“单云依赖”走向“混合轻量”

原方案将所有鸡蛋放在“微信云开发”篮子里，风险大且性能受限。新架构采用**“云开发鉴权存储 + 轻量服务器算力”**双核驱动。

### 1. 新架构分层图
```text
┌─────────────────────────────────────────────────────┐
│ 前端展示层（各端独立，不复用复杂逻辑）               │
│ PC端（原生HTML+CSS+JS） + 微信小程序（原生开发）      │
└───────────────────┬─────────────────────────────────┘
                    │ HTTPS调用
┌───────────────────▼─────────────────────────────────┐
│  接入鉴权层（微信云开发）                            │
│  职责：用户登录/票据校验 / 静态网站托管 / 敏感词过滤  │
└───────────┬───────────────────────┬─────────────────┘
            │                       │
            ▼                       ▼
┌───────────────────┐   ┌─────────────────────────────┐
│  NoSQL云数据库     │   │  计算密集型中间层（核心创新） │
│  （仅存结构化结果） │   │  腾讯云/阿里云轻量服务器     │
│                    │   │  部署 Node.js + Express     │
│                    │   │  职责：AI调用/语音评测转发   │
└───────────────────┘   └──────────┬──────────────────┘
                                    │
                          ┌─────────▼──────────┐
                          │ 外部API（大模型/评测）│
                          └────────────────────┘
```

### 2. 为什么这样改？
- **解耦AI逻辑**：云函数冷启动高达2~3秒，不适合对辩交互。轻量服务器（学生优惠约10元/月）常驻内存，响应<500ms。
- **成本透明**：即使将来小程序下架，PC端仍可通过独立服务器运行，不依赖微信生态。
- **便于调试**：AI返回的脏数据（如非JSON）可在服务器端用`json-repair`清洗后再下发，前端永不崩溃。

## 二、 数据库设计（精简至5张核心表，摒弃冗余）

删掉原方案的`dialogue_records`（对话明细）和`mentor_pairs`（暂缓），将过程数据以**JSON文本形式存入云存储**，数据库只存“结果快照”。

| 表名 | 核心字段 | 说明 |
| :--- | :--- | :--- |
| **`users`** | `_id, openid, role(pupil/college), nickname, grade, guardian_phone`, `ability_baseline`(JSON), `ability_latest`(JSON) | 增加监护人手机，符合未成年人保护法 |
| **`topics`** | `_id, title, category, difficulty, vocab_list`(array) | 词汇表用于AI生成时做“难度降级”过滤 |
| **`practice_records`** | `_id, user_id, topic_id, type(argument/speech), position, score(JSON)`, `audio_url`, `text_content`, `duration`, `created_at` | **只存最终结果**，不存对话过程 |
| **`assessments`** | `_id, user_id, type(baseline/milestone), score(JSON), created_at` | 专门用于前后测对比报表 |
| **`comments`** | `_id, pupil_id, college_id, content, audio_url, status(pending/done)` | 双向点评，仅存人工内容 |

> **关键优化**：模拟对辩的“每一轮对话”不上云数据库！改为在轻量服务器本地内存缓存（存最近10轮），对辩结束后生成**摘要JSON**，直接存入`practice_records`的`text_content`字段，并备份至云存储（节省数据库读写次数和费用）。

## 三、 后端核心实现（轻量服务器 Node.js + 云函数辅助）

### 1. 轻量服务器接口设计（处理所有AI重活）
部署在轻量服务器上的Express服务，对外暴露以下RESTful API（仅允许云开发环境IP或携带临时Token访问）：

| 接口 | 功能 | 核心优化点 |
| :--- | :--- | :--- |
| `POST /api/generate` | 生成立论框架 | **内置词汇过滤器**：如果生成词超出`topics.vocab_list`且非KET词汇，自动替换为括号内同义词。 |
| `POST /api/debate` | AI对辩单轮回复 | **带记忆窗口**：接收前端传来的`history`数组，返回纯文本，若超时自动切换备用模型。 |
| `POST /api/evaluate` | 语音评测 | **音频流直传**：前端直接传Base64音频（<1MB），服务器直接调用评测API，**不经过云存储中转**，评测完成后删除临时文件。 |
| `GET /api/growth/:uid` | 获取成长曲线 | 从云数据库聚合`practice_records`和`assessments`，用`Promise.all`并发查询，缓存结果5分钟。 |

### 2. AI容错与安全机制（代码级强制）
- **双模型降级**：主模型（豆包）超时3秒或报错，自动切换通义千问qwen-turbo（免费额度高）。
- **强制JSON修复**：引入`zod`库校验AI返回结构，捕获异常后使用`json-repair`库自动补全括号，前端永远得到`{code:200, data:{...}}`。
- **内容安全双保险**：AI生成文本返回前，**强制调用微信`security.msgSecCheck`**，若命中违规，直接返回预设安全文案（如“哇，这个问题好难，我们换个角度想想吧！”）。

### 3. 云函数保留职责（仅处理纯微信生态）
- `userLogin`：获取OpenId，首次登录写入`users`。
- `getTopicList`：简单分页查询。
- `uploadWork`：仅生成云存储上传签名，实际文件直传。

## 四、 前端开发策略（放弃跨端，拥抱原生）

### 1. 小程序端（原生开发）
- **不引入Taro**，直接使用微信开发者工具原生语法。理由：小学生界面需要大量自定义`button`、`image`和录音组件，原生对`wx.getRecorderManager`支持最稳定。
- **极简首页**：仅三个大圆角卡片（带图标）：“🎙️ 跟读挑战”（语音评测）、“🧠 立论小能手”（AI生成）、“📊 我的成就”（看板）。
- **录音优化**：采用**实时分帧上传**，用户松开按钮瞬间即开始评测，省去“上传等待”焦虑。

### 2. PC Web端（原生HTML+CSS+JS）
- **放弃Vue重构**，直接在原有`index.html`上增量开发。
- **登录简化**：由于PC端扫码登录对小学生不友好，**改用“手机号+验证码”登录**，后台通过`phone`字段关联微信`openid`（提前在后台绑定）。
- **适配双主题**：通过CSS变量一键切换“专业蓝”和“儿童黄”，无需打包。

## 五、 开发排期（严格按MVP功能切片，共6周）

将原方案的一锅端改为**3个Sprint，每个Sprint结束都有可演示的增量**：

| 阶段 | 时间 | 核心任务与**砍掉的功能** | 交付物 |
| :--- | :--- | :--- | :--- |
| **Sprint 1**<br>（地基期） | 第1-2周 | **做**：云环境搭建、轻量服务器部署、数据库建表、`userLogin`云函数。<br>**砍**：不做管理后台，不做结对，不做对辩。 | 小程序能登录并看到辩题列表，PC能手机号登录。 |
| **Sprint 2**<br>（核心闭环） | 第3-4周 | **做**：接入`/api/generate`立论、接入`/api/evaluate`跟读评测、个人简单记录列表。<br>**砍**：不做雷达图（先用ECharts CDN静态示例），不做AI对辩（太耗时）。 | **核心MVP**：用户可完成“选题->立论生成->录音评测”全流程，数据存入数据库。 |
| **Sprint 3**<br>（展示增强） | 第5-6周 | **做**：前端ECharts双雷达对比图（前后测）、管理端简易数据导出（直接查数据库导出CSV）、针对小学生的大字体UI优化。<br>**砍**：实时对辩（延后至V2.0）。 | **最终演示版**：满足项目验收的“前后对比”数据看板。 |

> **关于“模拟对辩”**：该功能对算力和提示词要求极高，为了6周演示不翻车，当前版本用**“预设话术分支”**替代（即根据用户关键词匹配固定反驳句），待项目通过验收后再用大模型替换。

## 六、 语音评测链路的专项优化（原方案短板）

原方案“上传->下载->评测”浪费时间和金钱，新方案采用**“前端直传 + 内存处理”**：

1. 小程序端录音生成**PCM/MP3**数据，转为Base64字符串（体积控制在500KB内）。
2. 直接POST到`/api/evaluate`，轻量服务器在内存中Buffer转存，调用百度语音评测API（支持Base64输入）。
3. 评测返回的`pronunciation`、`fluency`、`integrity`分数立即存入数据库，**整个链路耗时从8秒降至2.5秒**。
4. 设置文件**即时销毁**（`fs.unlinkSync`），不产生云存储费用。

## 七、 成本控制与合规红线（落地必备）

### 1. 费用预估（每月<100元）
- 轻量服务器（2核2G）：学生认证后约 **10元/月**。
- 大模型API：日均调用200次（小学生限20次/日），利用免费额度基本 **0元**。
- 云开发基础版：**免费**（配额足够百人级）。
- **节省项**：不使用云存储存音频，每月省去流量费约30元。

### 2. 未成年人合规落地
- **隐私协议**：首次登录强制阅读，并记录`agreement_version`。
- **数据最小化**：不采集精确位置、通讯录；`guardian_phone`仅用于紧急情况，加密存储。
- **日志留存**：所有AI交互记录（含输入输出）以JSON格式**备份至云存储**，保存180天以应对审查（利用云开发免费存储配额）。

## 九、 给开发者的最后警告与兜底

1. **AI不靠谱兜底**：若大模型API完全不可用（如网络封锁），服务器端启用**本地规则引擎**——根据辩题关键词（如“AI”关键词匹配“效率”“偏见”）输出模板化论点，确保演示永不翻车。
2. **数据库查询慢兜底**：管理端拉取全量数据时，若超过3秒，直接调用云开发的`database.collection.get()`并利用`skip/limit`分页，前端展示“数据加载中”占位，避免界面假死。
3. **小程序审核风险**：确保体验版中不包含“班级码”“社交排名”等容易触发社交资质审核的功能，正式版再通过`wx.getSetting`动态隐藏。
