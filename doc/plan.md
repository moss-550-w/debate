# 项目执行计划（Plan）

> 基于 [design.md](./design.md) 技术架构与 [new.md](./new.md) 功能清单重构。
> 目标：**4人团队、6周内交付可演示MVP**，完整跑通"**选题 → 生成辩论稿 → 录音 → AI评分 → 看前后对比数据**"的核心闭环。

---

## 1. 项目总览

| 项目 | 内容 |
|------|------|
| 名称 | 英语辩论能力训练平台（MVP版） |
| 核心目标 | 为小学生提供AI辅助的英语立论与跟读训练，通过前后测对比验证能力提升 |
| 交付 | 微信小程序（学生端） + PC Web端（教师/管理端） |
| 周期 | 6周，分3个Sprint |
| 团队 | 4人（前端×2 + 后端×1 + 测试/部署×1） |
| 成本 | 月费用 < 100元（轻量服务器10元/月 + 大模型API免费额度 + 云开发免费版） |

### 🟡 V2.0 规划（10项）—— 延后迭代

| # | 原功能 | 延期理由 | 当前状态 |
|:-:|--------|----------|:--------:|
| 1 | 即兴练习 | AI实时生成延迟高，仅内置5套固定应急题库 | 建空表 |
| 2 | 人工复评 | 保留数据库字段，V1.0教练暂不能改分 | 预留字段 |

| 5 | 教学资源库 | 改用云盘链接挂载在公告里 | 不做 |

| 10 | 奖项管理 | 不做自动证书，教练线下发奖状，线上只做Top3排行榜 | 降级 |

### ⚫ 永久砍掉（15项）—— 触碰红线

| # | 原功能 | 砍掉理由 | 替代方案 |
|:-:|--------|----------|----------|
| 1 | 视频录制 | 存储成本高 + 未成年人肖像权风险 | 仅录制音频MP3 |
| 2 | 对标示范 | AI视频标注需要CV算法团队 | 教练手动上传示范音频 |
| 3 | 社区分享 | 触碰小程序"社交"类目红线，审核必拒 | 数据仅在班级内可见 |
| 4 | 一对一指导 | 涉及IM和离线消息推送，开发量大 | 教练在个人档案写文字批注 |
| 5 | 提醒功能 | 微信模板消息限制严格 | 教练在企业微信群@未完成学员 |
| 6 | 创建比赛 | 过度设计，核心是日常训练 | 彻底砍掉 |
| 7 | 报名管理 | 同上 | 彻底砍掉 |
| 8 | 实时排行榜 | 实时聚合消耗性能，且制造焦虑 | 仅展示个人最佳进步幅度 |
| 9 | 比赛直播/回放 | 需CDN+推流，未成年人直播风险大 | 腾讯会议直播，平台放录播链接 |
| 10 | 数据分析报告 | 依赖大量数据，当前无数据源 | 彻底砍掉 |
| 11 | 多赛并行 | 同上 | 彻底砍掉 |
| 12 | 每日挑战 | 与"发布任务"高度重复 | 合并进任务发布 |
| 13 | 收藏夹 | 数据量小，浏览器书签即可 | 不做 |
| 14 | 优秀案例推荐 | 同"对标示范" | 教练手动置顶 |
| 15 | 肢体语言评分 | 虚标维度，无实际意义 | 去除 |

## 3. 技术架构

```
┌─────────────────────────────────────────────────────┐
│ 前端展示层                                          │
│ PC端（原生HTML+CSS+JS） + 微信小程序（原生开发）      │
└───────────────────┬─────────────────────────────────┘
                    │
┌───────────────────▼─────────────────────────────────┐
│  接入鉴权层（微信云开发）                            │
│  职责：用户登录/票据校验 / 静态网站托管               │
└───────────┬───────────────────────┬─────────────────┘
            │                       │
            ▼                       ▼
┌───────────────────┐   ┌─────────────────────────────┐
│  NoSQL云数据库     │   │  计算密集型中间层             │
│  （仅存结构化结果） │   │  轻量服务器（Node.js + Express）
│                    │   │  职责：AI调用/语音评测转发    │
└───────────────────┘   └──────────┬──────────────────┘
                                    │
                          ┌─────────▼──────────┐
                          │ 外部API（大模型/评测）│
                          └────────────────────┘
```

### 核心技术选型

| 模块 | 选型 | 理由 |
|------|------|------|
| PC前端 | 原生HTML+CSS+JS | 复用原型，零构建成本 |
| 小程序 | 微信原生开发 | 录音API最稳定，无需跨端兼容 |
| 后端主服务 | Node.js v18 + Express | 常驻内存，解决冷启动，方便调试AI |
| 后端辅助 | 微信云函数 | 仅处理登录/基础查询 |
| 数据库 | 云开发NoSQL（5张集合） | 与微信无缝集成，无需运维 |
| AI模型 | 豆包（主）+ 通义千问（备） | 免费额度充足，支持JSON输出 |
| 语音评测 | 百度智能云 | 支持Base64直传，维度精细 |

### 4.2 数据库建表

根据 [agent.md 第4节](agent.md#4-数据库集合设计5张表) 创建5个集合：

| 集合名 | 核心字段 | 说明 |
|--------|----------|------|
| `users` | openid, role, ability_baseline, ability_latest, agreement_version | 含监护人手机（加密） |
| `topics` | title, category, difficulty, vocab_list, status | 预置81条BP辩题 |

| `assessments` | user_id, type(baseline/milestone), score | 前后测对比 |
| `comments` | pupil_id, college_id, content, status | 人工点评 |

## 5. Sprint 2（第3-4周）—— 核心闭环

**目标**：用户可完成"选题→立论生成→录音评测"全流程，数据存入数据库。

### 5.1 后端核心接口

| 接口 | 功能 | 核心逻辑 | 对应V1.0功能 |
|------|------|----------|:------------:|
| `POST /api/generate` | 生成立论框架 | 调用豆包API → 词汇过滤器 → 安全检测 → 返回三段式骨架 | ①AI立论脚手架 |
| `POST /api/evaluate` | 语音评测 | 接收Base64音频 → 百度评测API → 返回(逻辑/论据/发音/流利度) | ②AI评估报告 ⑤语音转文字 |
| `POST /api/debate` | 模拟对辩（V1简化版） | 关键词匹配预设话术，不依赖大模型 | 预留 |
| `GET /api/growth/:userId` | 成长数据聚合 | 聚合practice_records + assessments → 返回 | ③历史记录 |

### 5.2 核心服务层

| 文件 | 职责 | 关键机制 |

| [backend/src/middleware/rateLimit.js](file:///d:/CODE/Debate/backend/src/middleware/rateLimit.js) | 限流 | 小学生每日20次调用限制 |

## 8. 关键风险与应对

| 风险 | 发生概率 | 影响 | 应对策略 |
|------|----------|------|----------|
| 大模型返回非JSON | 中 | 高 | json-repair修复 + 预设模板兜底 |
| 大模型API不可用 | 低 | 高 | 双模型降级（豆包→通义千问）+ 本地规则引擎 |
| 语音评测API限流 | 中 | 中 | 同一参考文本1小时内缓存不重复评测 |

| 轻量服务器宕机 | 低 | 中 | 云函数作为备用评测通道（保底方案） |
| 数据库查询慢 | 中 | 低 | skip/limit分页 + 前端"加载中"占位 |

## 10. 作弊条（快速参考）

### 10.1 统一API响应格式

```json
{
  "code": 200,     // 200成功，0业务失败
  "message": "ok",
  "data": null | object | array
}
```

错误码：400（参数错误）、401（未授权）、429（限流）、500（服务器错误）

### 10.2 数据库字段约定

- 集合名：全小写（`users`, `topics`, `practice_records`, `assessments`, `comments`）
- 字段名：`snake_case`（如 `ability_baseline`）
- 时间字段：`created_at`（Date类型）

### 10.3 代码命名约定

- 文件命名：`kebab-case`（如 `ai-service.js`）
- 变量/函数：`camelCase`（如 `getUserGrowth`）
- 环境变量：`UPPER_SNAKE_CASE`（如 `DOUBAO_API_KEY`）
